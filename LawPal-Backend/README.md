# ⚖️ Vakeel AI — Legal AI Backend

> An intelligent Indian Legal AI backend powered by **Hybrid RAG** (ChromaDB + BM25), **LLaMA 3.3 70B** via Groq, and optional **Redis** chat memory.

---

## 🧠 Tech Stack

| Component | Technology |
|---|---|
| **Web Framework** | Flask + Flask-CORS |
| **LLM** | LLaMA 3.3 70B Versatile (via Groq API) |
| **Vector Database** | ChromaDB (Persistent) |
| **Keyword Search** | BM25 (rank_bm25) |
| **Embeddings** | `BAAI/bge-large-en-v1.5` (SentenceTransformers) |
| **Chat Memory** | Redis (optional) |
| **Tokenizer** | tiktoken (cl100k_base) |
| **Deployment** | Docker / Hugging Face Spaces |

---

## 📁 Project Structure

```
Vakeel-Ai-backend/
├── app.py                  # Main Flask server — RAG pipeline & API routes
├── build_db.py             # One-time script to build ChromaDB + BM25 index
├── courtroom.py            # Courtroom simulation / trial logic
├── redis_chat_memory.py    # Redis-backed per-user chat memory module
├── requirements.txt        # Python dependencies
├── Dockerfile              # Docker deployment config
└── .env                    # Your local secrets (never committed)
```

> **Note:** The following files/folders are **not included** in the repo (too large or sensitive). You must generate them locally:
> - `chroma_db/` — vector database (generated by `build_db.py`)
> - `bm25_index.pkl` — BM25 index (generated by `build_db.py`)
> - `bm25_corpus.pkl` — BM25 corpus (generated by `build_db.py`)
> - `chunk_ids.json` — chunk ID mapping (generated by `build_db.py`)
> - `processed_legal_data.json` — your processed legal dataset (you must provide this)

## 🚀 Getting Started

### 1. Clone the Repository

```bash
git clone https://github.com/Amgothvijaykumar/Vakeel-Ai-backend.git
cd Vakeel-Ai-backend
```

---

### 2. Create a Virtual Environment

```bash
python3 -m venv venv
source venv/bin/activate        # On Windows: venv\Scripts\activate
```

---

### 3. Install Dependencies

```bash
pip install -r requirements.txt
```

---

### 4. Set Up Environment Variables

Create a `.env` file in the root directory:

```bash
touch .env
```

Add the following to your `.env` file:

```env
# Required: Groq API keys (comma-separated for rotation)
GROQ_API_KEYS=gsk_xxxxxxxxxxxx,gsk_yyyyyyyyyy

# Optional: Redis URL for chat memory (skip if not using Redis)
REDIS_URL=redis://localhost:6379

# Optional: Custom port (default: 7860)
PORT=7860
```

> 💡 Get your **free Groq API key** at [console.groq.com](https://console.groq.com)

---

### 5. Add Your Legal Dataset

Place your processed legal dataset in the root directory:

```
processed_legal_data.json
```

This is a JSON file containing legal document chunks with the following structure:

```json
[
  {
    "chunk_id": "unique-id-001",
    "chunk_text": "Section 302 of the Indian Penal Code...",
    "source_document": "Indian Penal Code, 1860.json",
    "section_id": "302"
  },
  ...
]
```

---

### 6. Build the Vector Database & BM25 Index

> ⚠️ This is a **one-time setup step**. It will embed all legal documents using `BAAI/bge-large-en-v1.5` and save the ChromaDB and BM25 index locally. It may take several minutes depending on dataset size.

```bash
python build_db.py
```

This will generate:
- `chroma_db/` — persistent vector database
- `bm25_index.pkl` — BM25 search index
- `bm25_corpus.pkl` — BM25 corpus
- `chunk_ids.json` — chunk ID list

---

### 7. Run the Flask Server

```bash
python app.py
```

The server will start on **http://localhost:7860**

You should see output like:
```
--- Initializing AI Legal Assistant Backend ---
✅ Loaded 2 Groq API keys.
✅ Embedding model loaded.
✅ Vector Database loaded.
✅ BM25 Index loaded.
✅ All data loaded.
 * Running on http://0.0.0.0:7860
```

## 📡 API Endpoints

### `GET /`
Health check — confirms the server is running.

**Response:**
```json
{ "message": "AI Legal Backend is running!" }
```

---

### `POST /ask`
Main RAG endpoint — answers Indian legal questions.

**Request Body:**
```json
{
  "query": "What is the punishment for murder under IPC?",
  "userId": "user_123"
}
```

**Response:**
```json
{
  "answer": "Under Section 302 of the Indian Penal Code, 1860, whoever commits murder shall be punished with death or imprisonment for life, and shall also be liable to fine..."
}
```

> `userId` is optional but required for Redis chat memory to work.

---

### `GET /history?userId=<id>&limit=<n>`
Retrieves recent chat history for a user *(requires Redis)*.

```
GET /history?userId=user_123&limit=10
```

**Response:**
```json
{
  "messages": [
    { "sender": "user", "text": "What is IPC 302?", "timestamp": "..." },
    { "sender": "bot", "text": "Section 302 deals with...", "timestamp": "..." }
  ]
}
```

---

### `POST /simulate_trial`
Simulates a courtroom trial for a given case description.

**Request Body:**
```json
{
  "description": "A person was caught driving under the influence of alcohol near a school zone."
}
```

## 🐳 Run with Docker

### Build the Docker Image

```bash
docker build -t vakeel-ai-backend .
```

### Run the Container

```bash
docker run -p 7860:7860 \
  -e GROQ_API_KEYS=gsk_xxxxxxxxxxxx \
  -e REDIS_URL=redis://host.docker.internal:6379 \
  -v $(pwd)/chroma_db:/app/chroma_db \
  -v $(pwd)/bm25_index.pkl:/app/bm25_index.pkl \
  -v $(pwd)/bm25_corpus.pkl:/app/bm25_corpus.pkl \
  -v $(pwd)/chunk_ids.json:/app/chunk_ids.json \
  -v $(pwd)/processed_legal_data.json:/app/processed_legal_data.json \
  vakeel-ai-backend
```

> Volume mounts are used to inject the large data files without baking them into the image.

## 🔴 Redis Chat Memory (Optional)

To enable persistent per-user chat memory:

1. **Install Redis locally:**
   ```bash
   # macOS
   brew install redis && brew services start redis

   # Ubuntu/Debian
   sudo apt install redis-server && sudo systemctl start redis
   ```

2. **Add `REDIS_URL` to your `.env`:**
   ```env
   REDIS_URL=redis://localhost:6379
   ```

3. Restart your Flask server — you'll see:
   ```
   ✅ Redis chat memory initialized.
   ```

If Redis is not configured, the server runs fine without it — just without conversation history.

## 🔑 Groq API Key Rotation

The backend supports **multiple Groq API keys** for automatic rotation when rate limits are hit:

```env
GROQ_API_KEYS=gsk_key1,gsk_key2,gsk_key3
```

Keys are rotated automatically. The current key index is tracked in `api_key_tracker.json` (local only, not committed).

## 🛡️ Guardrail System

The backend includes a lightweight **citation guardrail** that:
- Detects sections or Acts cited in the LLM response
- Checks if they are supported by the retrieved legal sources
- Appends a warning note if unrelated citations are found

## ⚠️ Troubleshooting

| Issue | Solution |
|---|---|
| `GROQ_API_KEYS not found` | Make sure `.env` file exists with valid key |
| `bm25_index.pkl not found` | Run `python build_db.py` first |
| `chroma_db collection not found` | Run `python build_db.py` to rebuild the DB |
| `Redis connection refused` | Start Redis service or remove `REDIS_URL` from `.env` |
| Embedding model slow to load | First run downloads ~1.3GB model, is cached after that |
| `All API keys rate limited` | Add more Groq API keys or wait for rate limit reset |
